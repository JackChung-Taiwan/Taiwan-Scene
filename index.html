GITHUB DESKTOP 實作指南

學生完整操作流程

從教師專案開始，建立自己的作品並公開展示：Fork → Clone → 修改 → Commit → Push → Pages

先看這個：Fork 必須在瀏覽器的 GitHub 專案網頁操作，不是在 GitHub Desktop 的「Let's get started」首頁。老師如果登入的是 JackChung-Taiwan 本人帳號，則只需 Clone 原專案，不需要 Fork 自己的專案。

Fork把老師的儲存庫複製到學生自己的 GitHub 帳號（線上副本）。
Clone將自己的線上副本下載到本機電腦，方便直接編輯。
Commit將修改記錄成一個版本；這個動作先儲存在自己的電腦。
Push把本機已提交的版本同步到 GitHub 線上儲存庫。
  1. 01

    建立 GitHub 帳號並安裝 GitHub Desktop

    要做什麼：到 GitHub 註冊頁建立學生自己的帳號，完成電子郵件驗證；再從 GitHub Desktop 官方網站下載安裝程式。

    安裝後開啟 GitHub Desktop，點選 Sign in to GitHub.com，依照瀏覽器畫面授權登入，回到 Desktop 確認已連結自己的帳號。

    為什麼？GitHub 是存放程式與圖片的線上平台；GitHub Desktop 則是不需要打 Git 指令也能操作版本管理的軟體。

    成功檢查：Desktop 可以看到自己的帳號，並能點選 Clone a repository from the Internet...。

  2. 02

    Fork：在網路上建立自己的版本

    用瀏覽器開啟 教師的 Taiwan-Scene 專案，在 GitHub 專案頁右上角點 Fork，選擇 Create a new fork。

    確認 Owner 是學生自己的帳號，Repository name 為 Taiwan-Scene，再按 Create fork。

    為什麼？學生不能任意直接修改老師的儲存庫；Fork 會建立自己的線上副本，修改與上傳都不會動到老師原專案。Fork 不是把檔案下載到電腦。

    成功檢查：網址變成 github.com/學生帳號/Taiwan-Scene，頁面中可看到來自老師專案的說明。

  3. 03

    Clone：將自己的 Fork 下載到電腦

    開啟 GitHub Desktop：File → Clone repository...；首頁也可以直接點 Clone a repository from the Internet...。在 GitHub.com 分頁選 學生帳號/Taiwan-Scene，或在 URL 分頁貼上學生自己的 Fork 網址。

    設定 Local path（本機存放位置，例如 Documents/GitHub），再按 Clone。如果出現詢問 Fork 用途的畫面，以個人練習為主可選 For my own purposes。

    為什麼？Clone 會把 Repository 中的圖片、HTML 和資料檔完整複製到你的電腦，讓你可以用檔案總管或編輯器修改。

    成功檢查：選擇 Repository → Show in Explorer，能看到 images/、index.html、data.js 等檔案。

  4. 04

    修改：替換圖片或編輯景點資料

    入門任務：在剛剛下載的專案內，開啟 images/，將自己拍攝或有授權的新照片改名為 001.jpg，覆蓋原本的 001.jpg，建議大小控制在 100–200 KB，不必一次更換全部 100 張。

    進階任務：以文字編輯器修改 index.html 的標題；或修改 data.js 中景點的 name、region、category。存檔後可直接開啟 index.html 預覽。

    為什麼？專案的資料與網頁都是一般檔案，GitHub Desktop 會自動偵測有沒有變更。要注意檔名及副檔名要一致，否則網站可能找不到圖片。

    成功檢查：切回 GitHub Desktop，左側 Changes 會出現已修改的 images/001.jpg 或其他檔案。

  5. 05

    Commit：記錄這次修改

    在 GitHub Desktop 左側 Changes 檢查要提交的檔案，確保旁邊有勾選。左下角 Summary (required) 輸入簡短說明，例如 Update Taipei 101 image 或 修改臺北101圖片，再點 Commit to main。

    為什麼？Commit 就像為作品建立帶有名稱的「版本存檔點」，日後可以查看每次修改的紀錄。Commit 只是本機存檔，尚未上傳到 GitHub。

    成功檢查：History 中能看到剛剛輸入的提交摘要；Changes 清空或減少。

  6. 06

    Push：將新版本送到 GitHub

    確定目前的儲存庫是 學生帳號/Taiwan-Scene，按 GitHub Desktop 上方的 Push origin。Push 完成後，回到瀏覽器開啟自己的 GitHub 儲存庫並重新整理頁面。

    為什麼？origin 代表目前這份本機 Repository 所連結的遠端儲存庫。Push 會把本機已 Commit 的版本同步到該遠端儲存庫；它不會自動幫你把修改送回老師的專案。

    成功檢查：自己的 GitHub 專案出現新的提交訊息與更新過的圖片或文字。

加分挑戰：使用 GitHub Pages 發佈自己的圖片網站

到學生自己的 GitHub 儲存庫，點選 Settings → Pages → Build and deployment。在 Source 選 Deploy from a branch，Branch 選 main、資料夾選 /(root)，再按 Save。

部署完成後，網址通常是 https://學生帳號.github.io/Taiwan-Scene/。第一次部署或 Push 更新後可能需要一段時間才會顯示最新內容。若 Pages 設定頁沒有此選項，請先確認學生專案的權限、公開狀態及帳號可使用的 Pages 功能。

常見問題與解決方式

找不到 Fork 按鈕？
要到瀏覽器打開老師的 GitHub 專案頁，而不是在 GitHub Desktop 首頁找。老師本人不需要 Fork 自己的專案。
Clone 清單找不到 Taiwan-Scene？
確認已經用學生帳號完成 Fork，Desktop 也登入同一個學生帳號；可改到 URL 分頁貼上自己的 Fork 網址。
Changes 沒有出現檔案？
請確認修改的是 Clone 下來的正確資料夾，而且已儲存。只下載 ZIP 並在其他位置修改，不會自動出現在 Desktop。
按了 Commit，但 GitHub 網站看不到修改？
Commit 只保存在本機，還需要按 Push origin。
Push 失敗或顯示沒有權限？
確認 Clone 的是學生自己的 Fork，不是老師原本的儲存庫；不要強制推送到教師帳號。
Pages 網站沒有更新或圖片破圖？
先確認已 Push，等待部署完成。圖片路徑、英文大小寫與副檔名必須與 data.js 一致。

學生完成檢查表

  • 有自己的 GitHub 帳號與 Fork
  • 已用 GitHub Desktop Clone 自己的專案
  • Changes 看得到修改紀錄
  • 已 Commit 並 Push 到自己的 Repository
  • 自己的 GitHub 網站看得到修改
  • 進階：自己的 GitHub Pages 網站可正常瀏覽
